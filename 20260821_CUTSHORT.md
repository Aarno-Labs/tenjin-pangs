# Cut/Shortcut Callsite Rewriting, Tiers 1–2 (Local-Flow and Accessor Patterns)

## Status

Proposed 2026-08-21. Not implemented. This document specifies the design and
implementation plan for the two cheapest tiers of pattern-guided constraint rewriting
derived from the Cut-Shortcut approach (`pdfs/cut-shortcut.pdf`; Yang, Ma, Reps, Tan,
Li, *Cut-Shortcut Whole-Program Pointer Analysis*, TOPLAS 48(3), 2026). The container
tier (root-keyed put/get shortcuts reusing the receiver-family inference) is
deliberately out of scope here and remains future work gated on this experiment's
results.

Relationship to prior work in this repository:

- `PANGS_ANDERSEN_RECEIVER_PAYLOADS` bought contextual precision by multiplying the
  memory-cell domain per receiver root. The 2026-08-01 corpus profile
  (`EXPERIMENT_HISTORY.md`) showed +623% wall and +940% RSS with broad precision churn;
  the feature stays opt-in. This experiment takes the opposite mechanism from the same
  paper: **zero new abstract objects, per-callsite edge rewriting in the ordinary
  context-insensitive constraint system**, where suppression of merged flows is expected
  to *reduce* propagation work rather than add it (the paper's RQ4 result: each pattern
  enabled made the analysis faster than the context-insensitive baseline).
- The suppressed-binding-edge mechanism (`receiver_payload_binding_edges()` checked at
  prepartition construction and constraint installation in
  `crates/pangs-solve/src/andersen.rs`) and the synthetic propagation-only cell
  discipline (memcpy edge summaries, receiver payload cells) are reused, not
  reinvented.

## 1. Problem statement

Context-insensitive Andersen merges flows at two kinds of helper functions that are
pervasive in C:

1. **Local-flow returns.** A function whose returned pointer derives only from its own
   parameters through local assignments (`select`-style pickers, defaulting helpers,
   `min`/`max` of pointers, identity-ish wrappers). Every caller's arguments merge into
   the parameter nodes, flow to the shared `Return` node, and pollute every callsite's
   result.
2. **One-level accessors.** A store `x->f = y` (or `*x = y`) where both `x` and `y` are
   parameter-derived, and the dual load-and-return getter. The store's constraint joins
   the *merged* `pts(param)` sets, so caller A's container receives caller B's payload;
   the getter returns the merged loaded values to every caller.

Both are exactly the "conflated path" shape the paper's local-flow ([CutLFlow] /
[ShortcutLFlow]) and field-access ([CutStore]/[ShortcutStore], [CutLoad]/
[ShortcutLoad]) patterns target. Dynamically, the value returned or stored at one
callsite derives from *that call's* actuals; the abstraction loses this only because
one parameter node summarizes all callers.

The costs today:

- spurious pointees on callsite results and on stored-through fields, which feed
  indirect-call envelopes, ModRef rows, and disposition blockers;
- cross-caller flow through shared helpers inflates the directed predecessor closure
  used by source-closed SCC slice admission for stranded indirect calls
  (`DESIGN_lite.md` §2D'), and inflates propagation volume in admitted regions.

Notably, much of the imprecision receiver payloads were built to fix does not require
receiver-relative cells at all: when two containers have distinct allocation sites,
evaluating the accessor's store/load against the *callsite's* argument sets restores
separation using the existing `(root, FieldLocation)` cells. Only same-allocation-site
internal storage needs more (the excluded container tier).

## 2. The rewrite, informally

Two mechanisms, applied at D' constraint-installation time over the frozen PAG. The
PAG itself is never modified.

**Cut.** Suppress a specific flow constraint that would carry merged flows:

- per-callsite: the flattened `Return(f) → result_i` Assign binding of an internal
  direct callsite (tier 1 and the getter);
- per-function: the Store flow join of a certified setter store (setter only, under a
  caller-completeness guard).

**Shortcut.** Install replacement constraints at each direct callsite, built from that
callsite's actual arguments:

- tier 1: one copy constraint `args[k] → result_i` per certified parameter index `k`;
- getter: a replica of the certified address chain applied to `args[k]` through
  synthetic propagation-only cells, ending in a Load into `result_i`;
- setter: the address-chain replica from `args[k1]` plus a Store of `args[k2]` through
  it, carrying the original edge's `access_bytes`.

Everything else about the solve is unchanged: same cell domain, same field domain, same
Ω regions, same admission machinery, same monotone on-the-fly call-graph discovery.
Both the cut sets and the shortcut constraint inventory are computed from the fixed PAG
*before* prepartitioning, and are fixed for the whole solve including resume rounds
(the paper's two-stage structure: pattern identification is purely local and
call-graph-independent; the fixpoint remains monotone because no edge is ever removed
mid-solve — suppressed constraints are simply never installed).

## 3. Certificates

All three certificates are regional walks over PAG edges owned by one function, in the
same style as the receiver-payload operation inference. Shared machinery: a bounded
backward producer walk with a per-walk node cap (default 64; overflow rejects the
certificate, never truncates it).

### 3.1 Shared node-safety conditions

A value node visited by any certificate walk must satisfy all of:

- every producing edge is owned by the function under analysis;
- the node is not the `result` of **any** `Callsite` (direct, indirect, or external).
  This is load-bearing: an indirect callsite's result has no producer edges in the
  fixed PAG — its `Return(target) → result` bindings are installed on the fly — so a
  naive walk would wrongly treat it as constant-like. The callsite-result check closes
  that hole for direct, indirect, and modeled-external results uniformly;
- no Ω seed targets the node (`SeedTarget::Node`);
- the node is not the destination of any `AddrOf`, `Load`, `Gep`, or `Memcpy` edge
  when the walk is a **value chain** (assign-only); a **address chain** additionally
  admits `Gep` producers as interior steps but still rejects `Load`, `AddrOf`, and
  `Memcpy` producers.

Walk leaves must be either a `Param { func, index }` of the function (recorded as a
shortcut source) or a constant-like node: no producer edges at all, plus every shared
condition above. Constant-like leaves contribute no shortcut source (a flattened
`return cond ? p : NULL` certifies with `p` as the only source; the null branch adds no
pointee in the baseline either).

### 3.2 Tier 1 — return-local-flow certificate

Function `f` is certified with parameter index set `K` when:

- `f` is defined, non-variadic, and has a `Return` node `R`;
- the backward closure of `R` over **Assign edges only** satisfies §3.1 and every leaf
  is a `Param` of `f` or constant-like;
- `K` = the set of leaf parameter indices; `K` may have several members (flattened
  phi/select).

Because the chain is assign-only, composition is the identity: the per-callsite
shortcut is a plain copy `args[k] → result_i` for each `k ∈ K`, with no synthetic
cells.

This is the analog of the paper's `⟨m,k⟩ ↦ ret^m` relation ([Param2Var]/
[Param2VarRec] + [CutLFlow]); their premise "not redefined in `m`" is our
single-producer-chain condition, which partial SSA gives us structurally.

### 3.3 Getter certificate (field-access, load side)

Function `f` is certified for a load edge `x = load y` when:

- the load edge is `x`'s **only** producer, and `x` satisfies §3.1;
- `R` is reachable from `x` through an assign-only chain in which every node satisfies
  §3.1 and `x` is the only leaf (so the returned value is exactly the loaded value);
- `y`'s backward closure over the **address chain** (Assign + Gep) satisfies §3.1 and
  terminates at exactly **one** `Param k` of `f` (single-root in v1; a mixed-root
  address phi fails open), with the ordered Gep steps recorded as
  `(byte_off | lane | unknown)` payloads;
- `f` is non-variadic.

Following the paper's refined field-load handling, only a single call layer is handled:
a wrapper whose return value is another function's call result is rejected by the
callsite-result condition. (Their conference version's nested-load handling was dropped
for cost and monotonicity reasons; we inherit that boundary deliberately.)

### 3.4 Setter certificate (field-access, store side)

Function `f` is certified for a store edge `Store { src: y, dst: x }` when:

- `x`'s address chain terminates at exactly one `Param k1` (conditions as in §3.3);
- `y`'s **value chain** (assign-only) terminates solely at `Param k2` leaves and/or
  constant-like leaves (`k1 == k2` is permitted; multiple value-leaf params are
  permitted and each becomes a shortcut source);
- **caller completeness** for `f` holds:
  - `f.address_taken == false` (so on-the-fly discovery can never activate `f` at an
    indirect callsite, and no callback path can reach it),
  - `f` is not exported / library-visible under the build mode's boundary seeding,
    and not external,
  - `f` is non-variadic,
  - every `Callsite` with `callee == f` is `CallKind::Direct`, has
    `external_boundary == false`, and supplies arguments at indices `k1` and every
    value-leaf index;
- the per-function certified-store cap (default 8, knob-overridable) is not exceeded.
  Exceeding the cap decertifies **all** of `f`'s setter stores (fail open as a unit,
  matching the paper's per-method cap semantics).

Caller completeness is what licenses suppressing the callee-side store join globally:
unlike the per-callsite return-binding cut, removing the Store constraint is a
function-level cut, and it is sound only if every dynamic invocation is covered by a
rewritten callsite. Tier 1 and the getter need no such guard because their cut is
per-callsite and `f`'s internal facts (including `pts(Return(f))`) remain complete for
every uncut consumer.

### 3.5 What is deliberately not certified (v1)

- Nested wrapper chains for stores (the paper's tempStore backtracking). Extension
  point; the certificate structure admits it later without changing the rewrite side.
- Multi-root address chains, unknown-offset roots reached through loads, and any chain
  touching memcpy.
- Indirect callsites as rewrite sites. An OTF-resolved indirect call to a certified
  function keeps its ordinary `Return → result` binding and full store handling.
- Variadic functions and K&R-style arity mismatches (arity checked per callsite; a
  mismatched callsite fails that callsite open in tier 1/getter and decertifies the
  setter entirely, since setter soundness quantifies over all callsites).

## 4. Soundness argument

The dynamic-derivation argument, per pattern:

**Tier 1 / getter (per-callsite cut).** Parameters are per-invocation SSA values. If
`R`'s value at runtime derives only from `f`'s parameters through assignments (tier 1)
or through one certified address chain and load (getter), then the value observed at
callsite `i`'s result derives from `args^i` through that same chain. The shortcut
constraints reproduce exactly that chain over `args^i`; the suppressed edge
`Return(f) → result_i` carried a superset (the merge over all callers) whose extra
elements are unrealizable at callsite `i`. All other flows into `result_i` (Ω seeds,
other assignments) are untouched. `pts(Return(f))` itself is still computed from `f`'s
unmodified internal constraints, so indirect callsites, differential oracles, and any
consumer that keeps the ordinary binding are unaffected. Partial application — cutting
some callsites and not others — is therefore sound callsite-by-callsite.

**Setter (function-level cut).** At runtime the store writes the value derived from
`args^i[k2]` through the address derived from `args^i[k1]`, for whichever callsite `i`
invoked `f`. Caller completeness (§3.4) guarantees the rewritten callsite set covers
every invocation; each rewritten callsite installs a Store whose address and value
operand sets are computed from that callsite's actuals. The union over callsites of the
per-callsite stores covers every dynamic store instance; the suppressed callee-side
join covered the same instances plus cross-callsite cross terms. The address operand
`x` keeps its complete points-to set (its producer constraints are untouched), which
matters for ModRef (§5.1).

**Refinement direction.** Every rewrite replaces a constraint by constraints whose
least-fixed-point contribution is a subset. Hence the rewritten solution is a
refinement of the baseline Andersen solution on every fact family, which gives the
one-directional A/B validation in §7: **any fact present in the rewritten run and
absent from the baseline run is a defect.** The existing
`Andersen ⊆ Steensgaard ⊆ FSA` tripwires are unchanged and must keep holding.

**Failure containment.** Certificates are computed from the fixed PAG only; a wrong
input assumption (int↔ptr forging, inline asm, unmodeled varargs) already carries an Ω
seed or violation finding, and §3.1 rejects any walk touching an Ω-seeded node. The
usual posture stands: everything here converts, at worst, unsupported shapes into
*no rewrite*, never into a missing flow — except for genuine certificate bugs, which
is what §7's one-directional differential and dynamic-trace checks exist to catch,
since a bad cut is an FN risk on the transformation-facing path.

## 5. Interactions and invariants

### 5.1 ModRef, mutation, and disposition

The PAG store/load edges are untouched; only the Andersen flow join of a certified
setter store is suppressed. Since the address operand's points-to set is unchanged,
ModRef's pointer-aware expansion of that access is unchanged, and the write remains
attributed to `f`. Direct-access recognition, stationarity (B1 reads syntactic
writers), escape narrowing, and the disposition fact producers read either the PAG or
the materialized solution; none of them reads "which constraints were installed."
Expected client-visible effect: ModRef rows, indirect-call envelopes, and pointee sets
may *narrow*; nothing may widen.

### 5.2 Steensgaard, admission, and fallback

C' (Steensgaard) is computed from the unrewritten graph and remains the complete
base-tier and fallback answer; a rewrite-induced refinement lost to an oversize
fallback is ordinary coverage loss. The prepartition graph is built from the actual
inclusion constraints, so it must see the rewritten shape: suppressed constraints are
excluded (via the same suppressed-binding check receiver payloads use at prepartition
construction) and shortcut constraints contribute their edges, with synthetic
address-chain cells as prepartition vertices exactly like receiver-payload cells.

Weak components will mostly *not* shrink — `arg → param` bindings remain, so callers
still union through parameter nodes. The structural win is directional: the
source-closed SCC slice for a stranded indirect-call operand no longer closes over
every caller's value flow through a shared helper's return, because `result_i`'s
predecessors become its own callsite's arguments. Slice sizes and admission outcomes
are first-class metrics in §8. The propagation-volume reduction inside admitted
regions is the other expected win and is visible in the existing pair counters.

Exhaustion semantics are unchanged: a resource limit abandons the whole Andersen tier
transactionally in favor of the complete Steensgaard result. Cuts never outlive the
solve they were installed for.

### 5.3 Monotone OTF call graph

Cut sets and shortcut inventories are fixed before the persistent solve starts and are
not revisited during resume rounds. OTF activation installs indirect-call bindings
only; those are never in a cut set (§3.5). A newly grounded direct binding does not
exist in this pipeline (direct bindings are flattened at PAG construction), so no
activation can race a cut decision. The subtractive differential oracle
(`20260723_MONOTONE_OTF_CG_PLAN.md`) runs on the same rewritten constraint system in
A/B-with-itself mode, and on the baseline system when used cross-mode; cross-mode
comparisons must apply the refinement direction, not equality.

### 5.4 Closed-producer / closed-consumer certificates

Both audits make subtractive decisions and must not silently trust adjacency that the
rewrite changed:

- The **closed-producer** graph consumes solved stores. A suppressed setter store
  must be replaced in the producer graph by the per-callsite synthetic stores (which
  name real caller-side value nodes and real destination cells), or — simpler v1 — any
  memory cell whose producers include a suppressed store's destination set is failed
  open (`explicit_open`). Synthetic address-chain cells follow the memcpy-summary
  precedent: outside the declared graph domain, unsupported-producer if encountered,
  never a closed terminal.
- The **closed-consumer** audit walks fixed PAG transfers, which are unrewritten and
  therefore a superset of installed flows: it stays sound without modification. Its
  named-function facts come from the rewritten solve, which is a refinement; a
  destination that lost a spurious function fact can only make the audit *more* likely
  to certify, which is correct because the fact was unrealizable.

Role assertions (a synthetic chain cell is never an allocation, pointee, named
function, or external region) are soundness guards, mirroring
`20260820_MEMCPY_EDGE_SUMMARIZATION.md` §5.6.

### 5.5 Other experiments

- **Hybrid bitsets, offline quotient, copy-SCC collapse:** orthogonal; shortcut copies
  are ordinary copy constraints and participate normally. The offline quotient must
  treat callsite result nodes with shortcut sources as multi-generator variables (it
  already protects call results as possible late generators; verify the protection
  covers results whose ordinary binding was cut).
- **Receiver payloads:** may not be combined in v1. The two features suppress
  overlapping binding-edge sets with different replacements; reject simultaneous
  enablement at option parsing rather than reasoning about composition now.
- **Memcpy edge summaries:** orthogonal (no certified chain may touch memcpy).
- **B2/B3:** unchanged and unaffected; B2's exact icall bindings remain pinned and
  take precedence as today. Tier 1 is the graph-rewrite generalization of the same
  regional reasoning B2 applies per-query; they coexist because B2 answers are exact
  and the rewrite only refines the non-exact solver path.

## 6. Implementation plan

### 6.1 Knobs

```text
PANGS_ANDERSEN_LOCAL_FLOW_SHORTCUTS=1     # tier 1: return-local-flow
PANGS_ANDERSEN_ACCESSOR_SHORTCUTS=1       # tier 2: getter + setter (implies tier-1
                                          #   machinery but not the tier-1 knob)
PANGS_ANDERSEN_SHORTCUT_WALK_CAP=64       # per-walk node cap
PANGS_ANDERSEN_SHORTCUT_STORE_CAP=8       # certified setter stores per function
PANGS_ANDERSEN_SHORTCUT_PROFILE=1         # inference + rewrite diagnostics
```

Defaults off. Tests scrub the knobs unless exercising them. Constants live in
`crates/pangs-solve/src/knobs.rs` beside the existing `PANGS_ANDERSEN_*` family.

### 6.2 Work items

**W1 — inference module + tier 1.**
A new `shortcuts` module in `pangs-solve` housing: the shared §3.1 walk (one
implementation parameterized by value-chain vs. address-chain edge admission), the
tier-1 certificate, and a `ShortcutPlan` value holding
`{ suppressed_binding_edges: HashSet<(NodeId, NodeId)>, callsite_copies, replicas }`.
Integration points in `andersen.rs`:

1. compute the plan immediately after PAG load, before prepartitioning;
2. generalize the existing `receiver_payload_binding_edges()` check sites (prepartition
   construction and constraint installation) to consult a merged suppressed-edge set;
3. install shortcut copies alongside base constraints, and register their edges with
   the prepartition builder;
4. metrics + `SHORTCUT_PROFILE` output: certified functions, per-reason rejection
   histogram, cut/installed counts.

**W2 — refinement harness.**
Extend the `differential` command with a `--refinement-baseline` mode: run baseline
and rewritten solves, assert one-directional containment on normalized exports
(icall target sets, node resolutions, pointee sets, ModRef row candidate sets, and
the unknown/external bits under the target-lattice order), and report the narrowed
facts. This harness is reused by tier 2 and by any future pattern.

**W3 — getter.**
Address-chain replication: allocate synthetic propagation-only cells per (callsite,
certified load), install `copy(args[k] → t0)`, the recorded Gep steps with identical
`byte_off`/`lane` payloads, and a Load into `result_i`; cut the callsite's return
binding. Cell role table entry (`shortcut-chain`) with the standard non-pointee
assertions.

**W4 — setter.**
Caller-completeness predicate (address-taken bit, build-mode export set, callsite
scan); store suppression via the merged suppressed-constraint set (extended to cover
Store edges, not just binding Assigns); per-callsite Store replicas carrying
`access_bytes`; the §5.4 closed-producer fail-open wiring plus its role assertions;
`SHORTCUT_STORE_CAP` unit semantics.

**W5 — measurement + decision.**
§8 corpus runs, `EXPERIMENT_HISTORY.md` entry, acceptance decision per §9.

W1–W2 land and are evaluated before W3–W4 begin; if tier 1 certifies a negligible
population on the corpus (§9 gate 5), stop there.

### 6.3 Estimated footprint

The inference walks are a few hundred lines plus tests (the receiver-payload inference
at ~300 lines is the closest analog); the rewrite plumbing reuses existing suppression
and synthetic-cell machinery. No PAG, PIR, schema, client, or disposition changes in
v1. No new export families: shortcut diagnostics ride the profile stream.

## 7. Correctness tests

### 7.1 Focused fixtures (each compared baseline-vs-rewritten, expecting exact
refinement and, where the pattern is absent, byte-identical solutions)

Tier 1:
1. Two callers of a two-parameter `select`-style helper: each result gets only its own
   arguments' pointees; `pts(Return(f))` unchanged.
2. `return cond ? p : NULL` (constant-like leaf) and `return cond ? p : q`
   (multi-param `K`).
3. Helper whose return chain passes through a direct-call result → not certified.
4. Helper whose return chain passes through an *indirect*-call result node with no
   fixed-PAG producers → not certified (the §3.1 callsite-result hole).
5. Ω-seeded node in the chain → not certified.
6. Certified helper also invoked through a function pointer: the OTF-installed indirect
   binding is not cut; the indirect callsite's result keeps merged facts; direct
   callsites are still refined.
7. Recursion returning a call result → not certified; walk-cap overflow → not
   certified.
8. Variadic and arity-mismatched callsites → callsite fails open, others refined.

Getter:
9. Two containers with distinct allocation sites through one `get` helper: each
   caller's result narrows to its own container's field contents; exact and lane Gep
   steps replicate; unknown-offset step replicates to the root's unknown summary.
10. Getter whose loaded value is not the sole return producer → not certified.
11. Mixed-root address phi → not certified.

Setter:
12. Two containers through one `set` helper: field cells receive only same-callsite
    values; the ModRef row for `f`'s store is unchanged in address candidates.
13. Address-taken setter → not certified; exported setter under library mode → not
    certified while the same module in executable mode certifies.
14. Store-cap overflow decertifies the whole function.
15. Setter + closed producers: destination cells behind a suppressed store either see
    the synthetic per-callsite stores or fail open; never certify through a gap.
16. Setter + closed consumers: a function-pointer payload stored through a certified
    setter reaches the same (or fewer) destinations, and unknown-caller narrowing is
    identical or strictly safer than baseline.
17. Function-pointer payloads through tier-1 and getter shortcuts reach the same
    indirect-call operands as baseline minus provably cross-callsite spurious targets;
    debug tripwires (`Andersen ⊆ Steensgaard ⊆ FSA`) hold.

Cross-cutting:
18. Injected exhaustion mid-solve reverts to the complete Steensgaard result; no cut
    survives into any exported artifact.
19. Copy-SCC collapse over shortcut copies; offline quotient enabled; hybrid bitsets
    enabled — solutions remain refinements and synthetic cells remain non-pointees.
20. Receiver payloads + either shortcut knob → loud option-parse rejection.
21. Fixture with no certifiable pattern: byte-identical exports with knobs on and off.

### 7.2 Pipeline and dynamic validation

- The W2 refinement harness on the small-program golden corpus: every export family is
  a refinement; the diff report itself is golden-filed for representative fixtures.
- `check-traces` on the instrumented corpus binaries used today: no dynamically
  observed callee outside the rewritten static envelope. This is the primary FN
  tripwire for bad cuts and is mandatory before any corpus precision claim.
- The full disposition + validation suites with each knob on: schema validation,
  manifest invariants, and the violation-taint completeness check unchanged.

## 8. Measurement plan

Baseline arm: knobs off. Experiment arms: tier 1 alone; tier 1 + tier 2. Release
builds, standard 200,000 budget, plus the forced-admission spot checks below. Follow
the `profile_receiver_payloads.py` harness shape (fresh binary, scrubbed experiment
environment, per-module A/B with caps and explicit timeout reporting).

Corpus: the 52-module standard set. Record per arm:

- certified-population metrics: functions certified per pattern, rejection histogram,
  cut edges, shortcut constraints, synthetic cells;
- wall, solve time, peak RSS; propagation pair counters (copy/load/store/GEP);
- prepartition metrics: largest weak component (expected ~unchanged), source-closed
  slice sizes and slice admissions for stranded icalls, oversize-fallback counts;
- precision deltas from the refinement harness: icall targets removed, ModRef
  candidates removed, unknown rows narrowed; disposition distribution deltas
  (`HOWTO_MEASURE_DISPOSITION_COVERAGE.md`);
- targeted cases: chibicc O1 (does tier 1/2 recover any part of the receiver-payload
  macro-handler result without the cell blowup?), YAPET O0/O1, gifsicle O0 slice
  admission, Slap disposition coverage (any movement on the
  `unknown-callee-taint`-blocked globals).

Every claim separates default-budget from forced-admission results, per the standing
rule that the budget must not be raised as a side effect.

## 9. Acceptance gates

Tier 1 may become default-on only if:

1. All focused and workspace tests pass; every completed corpus A/B pair is a strict
   refinement (equality allowed), with zero widened facts anywhere.
2. `check-traces` recall is unchanged on every instrumented benchmark.
3. Geometric-mean wall time does not regress beyond 3% and aggregate peak RSS beyond
   5% (the memcpy-experiment thresholds); a *reduction* is the expected outcome and
   its absence demands explanation before default-on.
4. Closed-producer/closed-consumer results are identical or strictly safer on the
   certificate matrix of §7.1 (15–16) run corpus-wide where enabled.
5. The certified population is material: as an initial bar, tier 1 certifies functions
   whose callsites cover ≥1% of direct callsites on at least a quarter of corpus
   modules, or produces a measurable precision/slice-size effect on at least one
   flagship target (Vim, PHP, chibicc, Slap). Below that, record the result and shelve
   the tier rather than carrying dead machinery.

Tier 2 additionally requires:

6. No ModRef, stationarity, or disposition fact widens on any pair, and the §5.4
   fail-open wiring is exercised by at least one corpus module (or proven unreachable
   by construction on all of them).
7. The setter caller-completeness predicate is audited against the build-mode export
   semantics with a library-mode corpus pass.

If tier 1 passes and tier 2 fails only on cost, tier 2 stays opt-in with its results
recorded; if either tier fails refinement or recall, the defect is a stop-ship
soundness bug, not a tuning matter.

## 10. Documentation and disposition of results

After measurement:

- record implementation and A/B results in `EXPERIMENT_HISTORY.md`;
- on default-on: update `DESIGN_lite.md` §2D' (a short "callsite-local cut/shortcut
  rewriting" paragraph beside the receiver-payload description, citing this document
  and the paper), and note in §4 that the local-flow/accessor share of the tier-E
  residue is now handled;
- update the `DESIGN_lite.md` §5 upgrade gates: the "context-insensitive icall residue"
  diagnosis gains an intermediate remedy (add a cut/shortcut pattern) between
  receiver-payload matching and building tier E;
- if the container tier is pursued next, it gets its own dated design document and
  must reuse the W2 refinement harness and the §3 walk machinery;
- if discarded, delete the knobs and record the certified-population evidence so the
  decision is reproducible.

The decision should answer four questions:

1. Are the certificates sound in the implementation (refinement + recall gates)?
2. What fraction of the corpus's helper population do tiers 1–2 actually cover?
3. Does suppression pay for itself in solve time, as it did for the paper's Java
   corpus, or is the C helper population too sparse for the propagation savings to
   show?
4. Do the slice-size reductions change any admission outcome that matters to a
   client, or is the benefit purely precision?
